# מדריך ייבוא תגובות יעד

## סקירה כללית

מערכת הייבוא מאפשרת לכם להכין תוכן תגובות יעד מראש בקובץ JSON ולייבא אותו ישירות לעורך. זה חוסך זמן ומאפשר עבודה מסודרת יותר.

**גרסה 2.0** מציגה מבנה חדש וגמיש יותר - היעדים הם עצמאיים לחלוטין ויכולים לייצג כל מיקום (עיר, מדינה, אזור).

## שלבים לייבוא

### 1. הכנת קובץ הייבוא

צרו קובץ JSON לפי הפורמט המוגדר. ראו דוגמה מלאה בקובץ `examples/lisbon-response.json`.

```json
{
  "version": "2.0",
  "destination": {
    "name": "ליסבון",
    "subtitle": "פורטוגל",
    "image": "https://...",
    "badge": "מומלץ למשפחות"
  },
  "match": {
    "score": 87,
    "reasons": ["מסלול ברור", "קהילה ישראלית"],
    "visaType": "ויזת נוודים דיגיטליים"
  },
  "narrative": {
    "introduction": "למה זה נכון לכם...",
    "pathway": "תיאור המסלול...",
    "fit": "איך אתם מתאימים...",
    "benefits": "יתרונות...",
    "highlights": ["יתרון 1", "יתרון 2"]
  },
  "sections": [
    {
      "key": "visa",
      "title": "ויזה ותהליך",
      "icon": "🛂",
      "content": "מידע מפורט על ויזה..."
    }
  ]
}
```

### 2. ייבוא לעורך

1. היכנסו לדף עריכת תגובה או יצירת תגובה חדשה
2. לחצו על כפתור **"ייבוא מקובץ"**
3. בחרו את קובץ ה-JSON שהכנתם
4. התוכן ייטען אוטומטית לטפסים

### 3. בדיקה ועריכה

לאחר הייבוא:
- בדקו שהתוכן נטען נכון
- ערכו התאמות אישיות לפי הצורך
- השתמשו בתצוגה מקדימה לוודא שהכל נראה טוב

### 4. שמירה ופרסום

- שמרו כטיוטה לבדיקה נוספת
- או פרסמו ישירות אם התוכן מוכן

## מבנה הקובץ

### פרטי היעד (destination)

מידע בסיסי על היעד - עצמאי לחלוטין, לא מקושר לטבלת מדינות.

| שדה | חובה | תיאור |
|-----|------|-------|
| `name` | כן | שם היעד (עיר, מדינה או אזור) |
| `subtitle` | לא | טקסט משני (למשל: שם המדינה לעיר) |
| `image` | לא | URL לתמונת היעד |
| `badge` | לא | תג מיוחד (למשל: "מומלץ במיוחד") |

### נתוני התאמה (match)

| שדה | חובה | תיאור |
|-----|------|-------|
| `score` | כן | ציון התאמה 0-100 |
| `reasons` | לא | סיבות התאמה (מוצגות כתגיות) |
| `visaType` | לא | סוג ויזה מומלץ |

### תוכן נרטיבי (narrative)

תוכן מותאם אישית המספר את הסיפור של המשתמש:

| שדה | שם בעברית | תיאור |
|-----|-----------|-------|
| `introduction` | הקדמה | למה היעד מתאים (ברמה גבוהה) |
| `pathway` | המסלול | תיאור המסלול/תהליך המומלץ |
| `fit` | איך אתם מתאימים | איך המשתמש עומד בדרישות |
| `benefits` | יתרונות | יתרונות עיקריים למשתמש זה |
| `highlights` | נקודות מרכזיות | רשימת נקודות מפתח |

### סקשנים גמישים (sections)

מידע מפורט לפי נושאים - ניתן להתאים לכל יעד:

| שדה | חובה | תיאור |
|-----|------|-------|
| `key` | כן | מזהה ייחודי (למשל: "visa", "education") |
| `title` | כן | כותרת בעברית |
| `icon` | לא | אייקון (אימוג'י) |
| `content` | כן | תוכן ב-Markdown |

#### סקשנים מומלצים

| מזהה | כותרת | אייקון |
|------|-------|--------|
| `visa` | ויזה | 🛂 |
| `safety` | ביטחון אישי | 🛡️ |
| `healthcare` | מערכת בריאות | 🏥 |
| `education` | חינוך | 🎓 |
| `employment` | תעסוקה | 💼 |
| `cost` | יוקר מחייה | 💰 |
| `community` | קהילה | 👥 |
| `transport` | תחבורה | 🚌 |
| `climate` | אקלים | 🌤️ |
| `housing` | דיור | 🏠 |
| `family` | חיי משפחה | 👨‍👩‍👧‍👦 |

ניתן להשתמש בכל מזהה שתרצו - הרשימה לעיל היא המלצה בלבד.

## תמיכה ב-Markdown

ניתן להשתמש בעיצוב Markdown בכל שדות הטקסט:

```markdown
**טקסט מודגש**
*טקסט נטוי*

- פריט ראשון
- פריט שני
- פריט שלישי

1. פריט ממוספר
2. פריט שני

[קישור](https://example.com)
![תמונה](https://example.com/image.jpg)

### כותרת משנה
```

## טיפים

### כתיבת תוכן אפקטיבי

1. **התאימו אישית**: הזכירו פרטים ספציפיים על המשתמש
2. **היו קצרים**: 2-3 פסקאות לכל שדה מספיקות
3. **השתמשו במספרים**: אחוזים, מחירים, מרחקים
4. **רשימות**: קלות יותר לקריאה
5. **אימוג'ים**: משפרים את הקריאות של סקשנים

### בדיקת הקובץ

לפני ייבוא, וודאו:
- הקובץ בפורמט JSON תקין
- כל המחרוזות בתוך גרשיים כפולים
- אין פסיקים מיותרים בסוף רשימות
- יש שדה `version` עם ערך "2.0"

### כלי עזר

- [JSON Validator](https://jsonlint.com/) - לבדיקת תקינות JSON
- Visual Studio Code - עורך עם הדגשת תחביר

## מעבר מפורמט 1.0

המערכת תומכת בייבוא קבצי פורמט 1.0 ישן עם המרה אוטומטית:

- `countryCode` הופך ל-`destination.name` (יש לעדכן ידנית)
- `matchScore` הופך ל-`match.score`
- `personalizedContent` ממופה ל-`narrative`
- `categoryOverrides` הופך ל-`sections`

מומלץ לעדכן קבצים חדשים לפורמט 2.0.

## פתרון בעיות

### הקובץ לא נטען

- וודאו שהקובץ בסיומת `.json`
- בדקו שה-JSON תקין
- וודאו שיש שדה `version` עם ערך "2.0"
- וודאו שיש `destination.name`

### תוכן לא מופיע

- בדקו שמות השדות (case-sensitive)
- וודאו שטקסט עם תווים מיוחדים מוברח נכון

### עיצוב לא תקין

- בדקו את תחביר ה-Markdown
- וודאו שאין תגי HTML בתוכן
